🔓 KidLock 儿童限时管控 App · 使用教程

适用于 Android 7.1.2（API 25）Amlogic arm64-v8a 电视盒子 · v1.0.0

一、安装与首次部署

1
安装 APK（盒子开启 ADB 调试后，在电脑上执行）： 
adb install -r app-release.apk
也可把 APK 放进 U 盘，用盒子自带文件管理器安装。
2
授予“使用情况访问”权限（用于检测当前前台应用并强制停止）： 
adb shell appops set com.kidlock.app GET_USAGE_STATS allow
3
打开一次 App 完成初始化：点开桌面图标后会先出现「家长验证」页， 输入任一组默认暗号即可进入（遥控器：↑↑↓↓←←→→； 手机：音量+音量+音量-音量-）。 Android 系统要求：应用被手动启动过才会收到开机自启广播。
4
激活设备管理员（防止儿童卸载 App）： 
adb shell dpm set-active-admin com.kidlock.app/.KidDeviceAdmin
也可在 App 内点击「激活设备管理员」按钮，在盒子弹窗中确认。
5
（可选）升级为设备所有者（防卸载强度最高，需在未登录任何账号的全新系统上执行）： 
adb shell dpm set-device-owner com.kidlock.app/.KidDeviceAdmin
⚠️ 执行顺序很重要：先做第 4 步防卸载，再交给儿童使用。卸载 App 前必须先在系统设置中停用设备管理员。
⚠️ 别忘记暗号：忘记后需通过 Web 控制台（需管理密码）查看或重设；两组暗号都可自定义，建议改成自己记得住的组合。

二、时间规则怎么算（核心概念）

模式含义典型用途
开放模式 OPEN 时间段内可以正常使用，时间段外自动锁屏 每天只允许看 18:00–20:00
禁止模式 BLOCK 时间段内强制锁屏，其余时间正常使用 禁止 22:00–次日 7:00 偷偷看电视
  • 多时段：可添加任意多条时间段，任意一条命中即生效。
  • 按周重复：每条时间段可勾选周一～周日中的任意几天（如仅周末开放）。
  • 跨午夜：开始时间大于结束时间即视为跨天（如 22:00 → 07:00），自动正确处理到第二天的结束时间。
  • 开始 = 结束：表示“全天”覆盖。
  • 规则完全依赖本机时钟，断网照常生效；修改系统时间会触发规则立即重新评估。

三、通过网页配置（推荐方式）

1
在同一局域网的电脑或手机浏览器中访问： 
http://<盒子IP>:9090
盒子 IP 可在盒子「设置 → 网络」中查看，或在 App 主界面的“服务地址”处直接显示。
2
页面会自动加载当前配置，无需输入密码。 只有保存配置、查看解锁序列或执行操作（临时解锁/立即锁定等）时，才会弹出密码验证框，输入管理密码（默认 123456）点确定即可。 安全起见，页面不回显现有密码——「管理密码」栏留空即表示不修改。 手机端已做适配：控件自动铺满屏宽、按钮加大、虚拟按键改为四列网格，小屏不再挤压错位。（v1.4.2）说明文字改为标题右侧的「?」浮窗，时间段 / 解锁序列 / 安全与服务默认折叠，点标题展开；新增「遥控器」卡片可进入全屏遥控器界面。

配置页各区域说明

区域操作说明
状态面板实时显示：当前是否锁定、生效时间段（按星期分组，如「周一到周五 18:00-20:00」）、下一状态切换时间、服务运行状态、访问地址；锁屏期间「前台应用」一栏显示的是锁屏前的应用。

遥控器（v1.4.2 新增 / v1.4.5 修订）点「打开遥控器」进入单独的全屏遥控器界面，含 ↑↓←→OK返回 以及返回键两侧的 音量−音量＋，共 8 个按键；手机浏览器同样适配。按键优先交给盒子自带的 8080 系统遥控服务执行，顶部状态条可查看连接状态并「重新检测」。首次进入需验证一次管理密码，左上角「返回主界面」回到配置页。
说明与折叠（v1.4.2）各功能项标题右侧的 ? 点击弹出说明浮窗；时间段、解锁序列、安全与服务默认折叠，点标题即可展开，页面更清爽。
管控模式选择「开放模式」或「禁止模式」。
时间段列表每条可设置开始/结束时间（±5 分钟、±1 小时步进微调）与生效星期；可增删多条。
解锁按键序列共两组暗号，同时生效：序列 1（遥控器）默认 ↑↑↓↓←←→→；序列 2（手机音量键）默认 音量+音量+音量-音量-。
出于安全考虑，打开页面时序列默认隐藏——每组的显示位置是一个「查看」按钮；点它并输入密码后显示序列，按钮同时变为「隐藏」，可随时再点一下隐藏回去。显示后可在「录入目标」里选择要改哪一组，用虚拟按键依次录入（方向键/音量键/OK/返回/菜单/空格/数字），点 ✕ 可删某一步。锁屏页与 App 验证页都不会显示序列，请家长自行牢记。
一次性解锁时长按键解锁后保持可用的分钟数，默认 30 分钟（范围 1–1440）。
管理密码 / 端口「管理密码」留空表示不修改（页面不回显）；填新值并保存即生效。改端口后需用新端口重新访问。
操作按钮「保存并立即生效」以及「立即锁定 / 临时解锁 / 重启 Web 服务 / 立即备份配置」点击后统一弹出密码框验证。
（v1.4.1）「临时解锁」与「清除临时解锁」已合并为一个按钮，按状态在「立即临时解锁 / 清除临时解锁」间切换。
手动锁定生效时：状态面板顶部徽标与「手动锁定」一行都会显示「手动锁定中」及自动恢复时间，「立即锁定」按钮本身变成「解除手动锁定」，点一下即可恢复定时规则。
立即锁定只锁到下一个时段翻转点，到点自动恢复定时规则，不会因点一次就让所有规则永久失效。
一次性解锁的特殊规则（防钻空子设计）：
解锁时长会自动取 min(设置的分钟数, 距离下一个允许时段的分钟数)。 例如允许时段 18:00–20:00，在 19:45 解锁 30 分钟 → 实际只解锁到 20:00； 20:00 一到立即重新锁屏，不可能借“解锁”混进下一个允许时段。

（v1.4.2 新增 / v1.4.5 修订）用网页遥控器操作盒子

入口：网页配置页 →「遥控器」卡片 → 点「打开遥控器」，会进入一个单独的全屏页面（地址 /remote），不再是配置页里的小面板。

八个按键：中间是 ↑ ↓ ← → OK 确认，底部一行是 − 音量 返回 (BACK) ＋ 音量；点击即发送到电视盒子，等同于按遥控器；手机浏览器为大按钮网格，手指点按即可。

按键如何生效（重点）：普通应用拿不到系统注入权限（INJECT_EVENTS），所以在 App 进程里怎么构造按键都会被系统拒绝——这就是「adb shell input keyevent 4 手动可以、网页里不行」的原因（adb shell 跑在 shell UID）。因此本版不再由 App 自己注入按键，而是优先复用盒子自带的系统遥控服务：
① 手机端「N1 遥控器」这类 App 之所以好用，是因为它只往盒子发 POST http://<盒子IP>:8080/v1/keyevent、内容为 {"keycode":4,"longclick":false}，真正执行按键的是盒子系统里跑在 system/root 身份下的常驻服务；
② KidLock 就装在这台盒子上，于是直接访问 127.0.0.1:8080 的同一个接口（由 App 后台转发，避免浏览器跨域并保留密码校验），方向键 / OK / 返回在第三方应用界面里都能生效；
③ 页面顶部状态条显示「盒子系统遥控服务已连接 / 未检测到」，服务后启动可点「重新检测」。N1 / YYF 等带该服务的固件装完即可用，无需 root、无需无障碍、无需任何手动配置。

音量键：直接调节系统音量，不需要按键注入权限，在桌面、直播 App、锁屏页等任意界面都生效。

盒子上没有 8080 服务时：自动回退到 ① 盒子已 root → 以 root 身份执行 su -c "input keyevent 4"（与 adb shell 等价）；② 盒子未 root → 点页面「去开启」，在电视「设置→无障碍」里打开「儿童限时管控」一次，由系统执行全局返回动作。该服务不读取屏幕内容、不收集信息。
状态栏会显示实际生效路径（盒子系统遥控服务 :8080/v1/keyevent / root input keyevent / 无障碍全局返回 / 应用内投递 / 系统音量服务），失败时列出每条路径的报错。

密码：首次打开会弹出管理密码框（默认 123456），验证一次后本次浏览会话内有效；若在本页已验证过密码，点「打开遥控器」会自动带上，无需重复输入。密码改动后会自动要求重新验证。

返回主界面：点左上角「返回主界面」回到配置页（注意：这不是发送 BACK 键）。锁屏页或家长验证页显示时，发送的按键会被它们接收，也可用来输入解锁序列。

部署前提：盒子提供 8080 系统遥控服务时什么都不用做（可先用手机端「N1 遥控器」App 验证）；没有该服务时才需要盒子已 root，或开启一次无障碍服务。首次触发 root 时若电视弹出授权框，请用遥控器点「允许」（只授权一次）。自家界面（主控台 / 锁屏页 / 家长验证页）与音量键不受此限制。若仍提示「发送失败」，先看顶部状态条与状态栏给出的具体原因。

五、锁屏期间的操作

动作效果
锁屏画面出现全屏覆盖、无法切后台；遥控器所有按键（方向/OK/返回/菜单/数字/电源等）均被拦截。同时正在播放的视频会被暂停并静音（含不响应暂停键的直播应用）。
输入解锁序列在锁屏画面上按出完整暗号——遥控器用 ↑↑↓↓←←→→，手机用 音量+音量+音量-音量-，任一组都可以。锁屏页不显示序列、也不显示输入进度，防止孩子观察模仿；两次按键间隔超过 3 秒自动重置；连续重复开头（如 ↑↑↑↓…）也能正确匹配。
序列正确立即解锁，进入“一次性解锁”倒计时；时间到自动重新锁屏。
到达解除时间无需任何操作，自动解锁并恢复正常使用。
想看看孩子在干什么（v1.4.1）手机/电脑打开 Web 后台 → 「当前画面」→ 点「查看当前画面截图」，即可看到盒子此刻的屏幕（含锁屏页）。无需密码，首次需在电视上允许一次截屏授权。

六、稳定性机制

  • 开机自启：监听开机完成、App 更新、时间变化等广播，启动后台监控服务。
  • 常驻保活：前台服务 + 每分钟心跳闹钟 + 服务被杀自动重启，重启后立即按规则补锁。
  • 强停当前应用（v1.4.0 重构）：到点按「先记下前台应用 → 媒体暂停键 + 暂停广播 → 弹锁屏抢占前台 → 0.8 秒后清理后台进程 → 1.2s / 2.5s 静音补刀」的顺序执行。因为前台进程杀不掉，必须等它退到后台才有效。
  • 锁屏静音兜底：部分 IPTV / 电视直播走视频轨、不响应媒体暂停键，且以前台服务常驻，进程可能一直清不掉。为此增加了独立于杀进程的静音链路——反复抢占音频焦点（逼播放器让出焦点而暂停/静音）+ 反射静音音乐流，且锁屏页全程持有音频焦点。因此即使应用没被关闭，也听不到声音；解锁或进入允许时段后自动恢复原音量。
  • 截屏不常驻占用（v1.4.1）：每次只抓一帧、抓完立刻释放虚拟屏，不在后台持续录屏；授权期间若正好处于锁屏，守护服务会暂缓抢占前台，避免把系统授权框顶掉。
  • 防卸载：设备管理员激活后，普通方式无法卸载；需先在系统设置停用管理员。

七、升级与配置不丢失（重要）

结论：正常覆盖安装 / 升级 App，开放时间段、密码、端口等所有设置都会保留。
操作方式配置是否保留
adb install -r 新.apk（覆盖安装）✅ 保留
盒子文件管理器直接安装新版 APK✅ 保留
先卸载再重新安装⚠️ 内部配置清空，但会从备份文件自动恢复
执行 pm clear（重置配置）⚠️ 内部配置清空，但备份文件仍在，会自动恢复
双保险存储机制：
  1. 内部存储（SharedPreferences）：App 升级、覆盖安装均保留。
  2. 外部备份文件：每次保存配置都会自动写入 /sdcard/KidLock/kidlock_config.json（若无存储权限则退回应用专属目录）。 App 启动时若发现内部配置为空，会自动从该文件恢复——卸载重装也能找回设置。
查看备份状态：App 主界面「配置备份」一行，或 Web 控制台的「配置备份」字段；也可点击 「立即备份配置」手动写一次。
⚠️ 如何彻底恢复出厂设置：需同时做两件事—— ① 执行 adb shell pm clear com.kidlock.app； ② 删除备份文件 /sdcard/KidLock/kidlock_config.json（含 App 专属目录下的同名文件）。 只做第一步的话，下次启动会自动恢复旧配置（这是为了防止误清除，属于设计行为）。

八、进阶：命令行 API（可选）

适合脚本/自动化场景，密码通过 pwd 参数传递：

# 查看状态（无需密码）
curl http://<盒子IP>:9090/api/status

# 读取配置（打开页面/接口均无需密码；密码与两组解锁序列都不下发，只返回步数 keyCount1/keyCount2）
curl "http://<盒子IP>:9090/api/config"

# 保存配置（body 为完整配置 JSON，必须含正确的 pwd 字段；password 留空=不修改密码；
#          不传 unlockKeys / unlockKeys2 = 保持原序列不变）
curl -X POST http://<盒子IP>:9090/api/config -d '{"pwd":"123456", ...}'

# 执行动作：unlock / lock / clearUnlock / restartWeb / backup / eval
curl -X POST http://<盒子IP>:9090/api/action \
     -d '{"pwd":"123456","action":"lock"}'

# 查看真实解锁序列（需密码，返回 unlockKeys / unlockKeys2）
curl -X POST http://<盒子IP>:9090/api/action \
     -d '{"pwd":"123456","action":"showKeys"}'

# v1.4.2：仅校验管理密码（遥控器页用，不下发任何配置）
curl -X POST http://<盒子IP>:9090/api/auth -d '{"pwd":"123456"}'

# 盒子自带的系统遥控服务协议（N1 / YYF 固件）
# KidLock 从本机 127.0.0.1 转发调用同一个接口，由系统身份执行按键：
# curl -X POST http://127.0.0.1:8080/v1/keyevent -d '{"keycode":4,"longclick":false}'

# 发送遥控器按键（首选转发给上面的 8080 系统服务，失败自动回退 root / 无障碍）
# key: 19上 20下 21左 22右 23确认 66回车 4返回 24音量+ 25音量-
# 成功 {"ok":true,"path":"盒子系统遥控服务 :8080/v1/keyevent"}；失败 {"ok":false,"error":"按键注入失败：..."}
curl -X POST http://<盒子IP>:9090/api/key \
     -d '{"pwd":"123456","key":19}'

# 重新探测盒子系统遥控服务（服务后启动 / 换网络时用，前端「重新检测」按钮）
curl -X POST http://<盒子IP>:9090/api/action \
     -d '{"pwd":"123456","action":"reprobeBridge"}'
# 返回 {"ok":true,"bridge":true,"detail":"已连接 127.0.0.1:8080"}

# 打开电视的系统无障碍设置（无 8080 服务且未 root 时开启「儿童限时管控」）
curl -X POST http://<盒子IP>:9090/api/action \
     -d '{"pwd":"123456","action":"openAccessibility"}'

# v1.4.2：打开全屏遥控器页面（浏览器直接访问）
# http://<盒子IP>:9090/remote

九、常见问题（FAQ）

问题解决方法
网页打不开确认手机/电脑与盒子在同一局域网；确认端口未被改动；在 App 主界面确认 Web 服务已运行；必要时点「重启 Web 服务」。
遥控器按键没反应① 确认管理密码正确；② 看遥控器页顶部状态条：显示「盒子系统遥控服务已连接」说明走 8080 系统服务（最可靠），显示「未检测到」时点「重新检测」，或先用手机端「N1 遥控器」App 验证盒子 8080 服务是否活着；③ 看状态栏返回的具体路径原因；④ 锁屏页 / 家长验证页显示时按键会被它们接收（属预期，可用来输解锁序列）；⑤ 设为 Device Owner / 系统应用后重试。
返回键失效 / 提示「按键注入失败」，但 adb shell 手动可以根因是应用 UID 没有 INJECT_EVENTS，adb shell 是 shell UID 所以手动可以。现已改为优先复用盒子自带的 POST 8080/v1/keyevent 系统遥控服务（与手机端 N1 遥控器同一个接口，由系统身份执行），N1 / YYF 类固件装完即可用、零配置；盒子上没有这个服务时才自动回退到 root su -c "input keyevent 4" 或无障碍全局返回。状态栏显示实际生效路径，失败时列出每条路径的报错。

点过「立即锁定」后，到开放时段也不解锁旧版手动锁定是持久化标记且优先级高于时段判定，会把定时规则永久压住。新版已修复：手动锁定只到下一个时段翻转点自动失效（状态面板会显示恢复时间），点「解除手动锁定」可立即恢复规则。若还没替换新 APK，可执行 POST /api/action {"pwd":"...","action":"clearUnlock"} 立即清除。
还没到开放时段，盒子却显示「未锁定」旧版跨零点段（如周六 20:00-次日09:30）会让生效日当天凌晨也被算作开放。新版已修正：该段只在生效日 20:00 之后、次日 09:30 之前生效；升级后按新规则判定。
