## v1.4.2 修订：修复遥控器返回键失效 + 增加音量加减（19:0x）

用户反馈「返回按键失效，提示按键注入失败，旁边增加音量加减按键」。**版本号保持 1.4.2 不变**（属修订，未升 1.4.3），**未编译**（沿用约定）。

**根因判断**：本 App 无系统签名 / 无无障碍服务 / 无 `INJECT_EVENTS`（signature 级，普通应用拿不到）；BACK 又会被不少盒子的 `PhoneWindowManager` 额外拦截，且 `Instrumentation.sendKeyDownUpSync(4)` 常「不抛异常但静默丢弃」造成假成功，短路掉真正有效的降级路径。另外 `LockScreenActivity` / `GateActivity` 的 `dispatchKeyEvent` 本就吞掉全部按键并喂给解锁序列。

**技术方案（分场景，按 key 与前台窗口分流）**
1. `KeyInjector.kt` 重写：`send(context, keyCode)` 新签名；白名单扩为 `19,20,21,22,23,66,4,24,25`；新增 `lastError`（逐条失败原因）与 `lastPath`（实际生效路径）。
   - 音量 24/25 → `AudioManager.adjustStreamVolume(STREAM_MUSIC, …, FLAG_SHOW_UI)`，全局生效、无需注入权限；失败再降级注入。
   - 自家界面在前台（非音量键）→ **优先直接投递** `dispatchKeyEvent(DOWN/UP)`，完全绕开系统注入；锁屏页照常喂解锁序列。
   - 第三方界面 + BACK → `input keyevent 4` → 反射 `InputManager.injectInputEvent()` → Instrumentation（放最后避免假成功）。
   - 第三方界面 + 方向键/OK → 保持原顺序 Instrumentation → 反射 → shell。
   - 反射事件用 **API 13+ 10 参 `KeyEvent` 构造**：`deviceId=-1`、`FLAG_FROM_SYSTEM`、`InputDevice.SOURCE_KEYBOARD`，与系统 `input` 命令一致（勿用 `setSource()`，低版本兼容性存疑）；`getMethod` 第二参数用 `Int::class.javaPrimitiveType` 而非 `Integer.TYPE`（Kotlin 解析风险）。
2. `KidLockApp.kt`：`registerActivityLifecycleCallbacks` + `WeakReference` 维护 `foregroundActivity`，onResumed 设置、onPaused/onDestroyed 清空；7 个回调全实现，显式 `KidLockApp.markXxx()` 调用避免匿名内部类作用域歧义。
3. `ConfigWebServer.kt`：`KeyInjector.send(appContext, key)`；成功回 `path`，失败回 `lastError` 拼进 `error`（不再只回笼统一句）。

## v1.4.2 二次修订：返回键仍失效 → 定位到「进程身份」（19:1x）

用户反馈「返回键还是不行，**手动注入可以**」，并给出参考文章 `https://blog.csdn.net/qq_40582463/article/details/105253686`（斐讯 N1 WiFi 遥控器）。文章要点：手机端只发 HTTP（`/v1/keyevent {"keycode":4}`），真正执行命令的是**盒子上具备系统/root 权限的服务**；休眠唤醒靠官改固件的 root + telnet 执行 `echo mem > /sys/power/state`。

**上一轮诊断错在把问题归为「BACK 被固件策略拦截」**。真正根因是 **UID / 权限身份**：`INJECT_EVENTS` 是 signature 级权限，普通应用拿不到；应用进程里无论 `Instrumentation`、反射 `InputManager.injectInputEvent()` 还是 `Runtime.exec("input keyevent 4")`，UID 都是 `u0_aXX`，全会被 InputManagerService 拒掉。用户 `adb shell input keyevent 4` 能成功是因为跑在 **shell UID**。构造 KeyEvent 再讲究也没用。

**最终方案（两条高权限通道，二选一即可）**
1. **已 root → 零配置**：`KeyInjector` 优先 `su -c "input keyevent <code>"`，身份等价 adb shell。`hasSu()` 用 `su -c id` 探测一次并缓存；`exec()` 用 `ProcessBuilder.redirectErrorStream(true)` 合并 stdout/stderr，`CountDownLatch` + 独立 waitFor 线程做超时（API 25 无 `Process.waitFor(timeout)`）；`looksFailed()` 识别 `Exception/Permission/denied/not found`，shell 真实报错经 `lastError` 回传前端。首次 su 可能弹 root 授权框，文档已提示用遥控器点一次「允许」。
2. **未 root → 开启一次无障碍**：新增 `KidLockAccessibilityService`，`performGlobalAction(AccessibilityService.GLOBAL_ACTION_BACK)` 由系统执行全局返回，不需注入权限。配套 `res/xml/accessibility_service_config.xml`（`canRetrieveWindowContent=false` / `canPerformGestures=false` / `typeWindowStateChanged`，事件回调全忽略）、`strings.xml` 的 `accessibility_desc`、Manifest service 声明（`BIND_ACCESSIBILITY_SERVICE` + meta-data）。**注意常量要写全限定 `AccessibilityService.GLOBAL_ACTION_BACK`**，避免 companion object 作用域歧义。

**发送顺序**：音量 → `adjustVolume` → shell → 反射 → Instrumentation；自家界面前台 → `dispatchToSelf` → true；第三方 + BACK → shell(root) → 无障碍 → 反射 → Instrumentation；第三方 + 方向键 → shell(root) → Instrumentation → 反射。

**接口/前端**：`/api/status` 增 `accessibility`；`/api/action` 增 `openAccessibility`（`Settings.ACTION_ACCESSIBILITY_SETTINGS` + `FLAG_ACTIVITY_NEW_TASK`，需密码）；`/api/key` 失败时附加开启引导；`statusJson()` 的版本兜底改为空串（不再硬编码 1.4.2）。`remote_page.html` 增 `#a11yBar` / `#a11yBtn` 提示条、`refreshStatus(first)`、`visibilitychange` 回页面自动刷新状态；`config_page.html` 的 `HELP.remote` 同步说明。

**校验**：node 静态 138 项全通过（17 个 Kotlin 文件括号状态机、JS `new Function()`、DOM id、静态标签、8 个 data-key、Manifest/资源交叉引用、三文档一致性、发布说明章节一~十二）；Python ElementTree 校验 4 个 XML 合法；`javap -protected android-36/android.jar` 确认 `GLOBAL_ACTION_BACK` / `performGlobalAction` / `onServiceConnected` / `Settings` 常量均为可用 API。临时脚本已删。**未编译**（沿用约定）。
