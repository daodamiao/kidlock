## v1.4.4：无障碍配置编译修复自检 + 版本同步（10:2x）

用户反馈「无障碍服务 xml 中多处错误影响编译，我已做修改，并更新版本 1.4.4」。

**根因坐实**：用户删除了 `res/xml/accessibility_service_config.xml` 里的 `android:flags="flagDefault"`。查 SDK `platforms/android-36/data/res/values/attrs.xml` 的 `AccessibilityService` styleable（4350 行起）：合法属性是 `android:accessibilityFlags`（4459 行），**根本不存在** `android:flags`；AAPT2 在 link 阶段会直接报 error。`flagDefault` 本就是默认行为，删除对服务无任何影响。当前保留的 `description` / `accessibilityEventTypes` / `accessibilityFeedbackType` / `notificationTimeout` / `canRetrieveWindowContent` / `canPerformGestures` 全部在 SDK 定义内。

**自检**：`aapt2 compile --dir res` EXIT=0；把 `package="com.kidlock.app"` 注入临时 Manifest 副本后 `aapt2 link` EXIT=0（直接 link 源码 Manifest 会报缺 package，这是 Flutter/AGP 项目常态，namespace 由 Gradle 注入，不是项目错误）。`strings.xml` 的 `accessibility_desc` 存在；Manifest service 声明、`@xml/accessibility_service_config` 与 `KidLockAccessibilityService.kt` 三者一致。

**版本同步**：`pubspec.yaml` = `1.4.4+9`、`build_task.bat` = `app-release-v1.4.4.apk`（用户手动改，未动）。同步：两页版本徽标、README 当前版本块、发布说明标题/新增 v1.4.4 更新行/兼容范围/ADB 示例/发布包名、使用教程页脚、MEMORY.md 当前版本与版本线。发布说明新增 `## 五、v1.4.4 更新日志`（编译修复 + 自检结论），原五~十三顺延为六~十四。**历史功能标记（v1.4.2 引入 / v1.4.3 修复）保留不改**。

## 遥控器仍不可用 → 改用盒子 8080 系统遥控服务（10:4x）

用户反馈「遥控器功能还是不行」，给了可用参考项目 https://github.com/Jimmuy/N1_controler 。

**根因再定位**：读 README + `ControllerActivity.kt` + `HttpManager.java` + Manifest 后确认，该项目是**手机端 App**，自身完全不注入按键（Manifest 只有 ACCESS_WIFI_STATE / ACCESS_NETWORK_STATE），它只往盒子发 `POST http://<盒子IP>:8080/v1/keyevent`，body `{"keycode":N,"longclick":false}`；真正执行 `input keyevent` 的是盒子 YYF 系统里跑在 system/root 身份的常驻服务。前两轮都在 App 进程内折腾 root / 无障碍 / InputManager 反射，方向偏了——KidLock 就装在这台盒子上，直接调本机 8080 即可；用户说「这个可以用」说明服务是活的。

**代码改动**
- 新增 `N1KeyBridge.kt`（object）：纯 JDK `HttpURLConnection`；`probe()` 只做 TCP connect（400ms，先 127.0.0.1，失败再枚举本机 IPv4，不发探测请求、无副作用）；端口未开放缓存 30s 快速失败；`send()` POST JSON，2xx 才算成功，读 body 前 160 字符用于诊断；非 2xx / 异常即 `invalidate()` 作废缓存并降级；提供 `isAvailable()` / `status()` / `reset()` / `lastError`。
- `KeyInjector.send()`：音量仍优先 `AudioManager`；**其余所有按键（含 BACK）首选 `viaBoxService()`**，之后才是 `dispatchToSelf` → root shell → 无障碍(BACK) → InputManager → Instrumentation。成功 `path` = `盒子系统遥控服务 :8080/v1/keyevent`。
- `ConfigWebServer`：`statusJson()` 加 `bridge` / `bridgeDetail`；`/api/action` 加 `reprobeBridge`；按键失败提示改为先引导「重新检测 8080」。
- `AndroidManifest.xml` 显式 `android:usesCleartextTraffic="true"`。
- 前端 `remote_page.html`：新增顶部 `.bridge` 状态条 +「重新检测」按钮、`reprobeBridge()`、`refreshStatus()` 同时管 `a11yBar`（桥接可用时隐藏无障碍引导）、帮助浮窗重写；`config_page.html` 的 `HELP.remote` 重写。
- 文档：`README.md`（目录结构、§五.7 整节重写、Web API 表、状态字段表、FAQ）、`发布说明.md`（开头新增「本轮修订」条、核心功能行、FAQ）、`使用教程.html`（遥控器章节、API 示例、区域表、FAQ）同步。
